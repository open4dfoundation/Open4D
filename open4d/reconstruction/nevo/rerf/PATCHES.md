# Vendored ReRF

Source: <https://github.com/aoliao12138/ReRF> (CVPR 2023), cloned at depth 1.

**Unmodified.** Every file under this directory is upstream's, byte for byte.
Nothing is edited; four things are *deleted*, none of them code:

- `.git/`
- `ac_dc/CMakeFiles/`, `ac_dc/CMakeCache.txt`, `ac_dc/Makefile`,
  `ac_dc/cmake_install.cmake` -- 11 MB of object files and CMake state from the
  machine that built `ac_dc`, describing paths that do not exist here. The
  `.so` files they produced are kept and are what actually gets loaded; the
  intermediates cannot rebuild anything, because the C++ sources were never
  published (see below).
- `assets/teaser.png` -- 3.5 MB README illustration.

That takes the vendored tree from 18 MB to 3.3 MB. NeVo's own changes live
outside it entirely:

- `nevo/rerf_env.py` supplies the load-path and CWD setup upstream expects
  from its `LD_LIBRARY_PATH=... PYTHONPATH=... python run.py` wrapper.
- `nevo/importance.py` re-implements the part of
  `lib.dvgo.DirectVoxGO.forward` it needs rather than patching in an extra
  return value. `nevo.importance.check_against_rerf` asserts the two produce
  identical weights, so the copy cannot drift silently.
- `configs/nevo/*.py` are generated by `orbitnevo/train.py`. They are new
  files in an upstream directory, not edits to upstream configs.

ReRF is released for non-commercial use only and its code base derives from
DVGO. See `../citation.txt`.

## Things upstream does that are load-bearing here

- `ac_dc/` ships **only** as a CPython 3.8 binary (`ncvv_ac_dc.cpython-38-*.so`)
  with no sources, and its `RUNPATH` points at `/home/ubuntu/pybind11_numpy/build`
  -- a directory on the machine that built it. Hence the Python 3.8 environment
  and the explicit `dlopen` in `nevo/rerf_env.py`. There is no way to rebuild
  it for a newer Python without the upstream authors publishing the sources.
- `codec/quant.py` reads `./codec/quant.npy` at import time, so the CWD must be
  this directory when `lib.dvgo` is first imported.
- `lib/dvgo.py` calls `torch.set_default_tensor_type('torch.cuda.FloatTensor')`
  at import. Anything imported after it gets CUDA tensors by default.
- `lib/dvgo.py` JIT-builds three CUDA extensions on first import. The first
  run in a fresh environment takes a couple of minutes.
